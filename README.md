# EasyPub Web

把 TXT 小说转成 EPUB 3 的纯前端工具。双击 `index.html` 就能用，不装软件、不上传文件、不需要服务器。

源自 2015 年的桌面软件 EasyPub 的重写。原版依赖 .NET 运行时和已停止维护的 kindlegen，这里把整条链路搬到了浏览器：解析、分章、排版、封面、打包全部在本地完成，零第三方依赖。

## 特性

- **纯离线**：22 MB 的 TXT 从头到尾不离开本机，没有上传、没有账号
- **零依赖零构建**：没有 npm 包、没有打包步骤，`git clone` 后直接打开就能跑
- **快**：766 万字 / 1076 章，从导入到导出 EPUB 约 1.3 秒
- **章节树可拖动**：封面页、目录页、内容简介与正文章节一视同仁，可开关、可改名、拖动即调整全书顺序
- **实时预览**：调字号行高、写自定义 CSS，都能立刻看到排版效果

## 快速开始

```bash
git clone <this-repo> epubify
cd epubify
```

直接用浏览器打开 `index.html` 即可（Chrome / Edge / Firefox / Safari 均可）。

也可以起一个本地静态服务器：

```bash
python -m http.server 8848
# 打开 http://127.0.0.1:8848
```

导入方式：把 `.txt` 拖进窗口，或点右上角「导入 TXT」。

## 使用说明

### 分章规则

自动识别 UTF-8 / GBK 编码，按规则切分章节。两种配置方式：

- **可视化构建**：勾选「前缀（第 / 卷 / Chapter）+ 序号写法 + 后缀（章 / 回 / 节 / 集 / 卷 / 部 / 篇）」，实时生成正则
- **直接写正则**：给出完整正则表达式，按行匹配

面板会显示「实际生效的正则」和「预计识别 N 章」，改完先看数字，满意再点「应用并重新分章」。

内置四套预设：中文网文、卷章两级、英文 Chapter、纯数字行。

> 默认规则会过滤「像正文的假标题」。比如正文里的 `第一部分首先揭示了……` 不会因为以「第一部分」开头被误切成章——原版 EasyPub 在这里会误判，产物目录里能直接看到。

### 章节树

- **双击标题**或点行内 `✎` 改名
- 悬停显示 `−` `+`（调整目录层级）、`✎`、`×`（删除）
- **按住拖动**任意行调整顺序，蓝线指示落点
- `Ctrl` 点选、`Shift` 连选、`Ctrl+A` 全选，选中后可批量改层级 / 删除 / 恢复

**封面页**和**目录页**也是章节，会出现在电子书目录里。在「书籍信息」页勾选即插入，在列表里删除即关闭。它们和正文一样可以改名、拖动。

第一个真章节之前的内容（书名、作者、简介）会自动成为「内容简介」页。

### 版式与样式

「版式」页控制字号、行高、首行缩进、段间距、对齐、页边距。

「自定义样式」页可以：

- 载入当前生成的 CSS 当底稿，改哪条写哪条
- 上传 `.css` 文件
- 选择「追加覆盖」或「完全替换」

页面上附了可用的类名对照表（`p`、`p.a`、`h2.titlel2std`、`.tocpage` 等）。改动实时反映在「预览」页。

### 封面

三种模式：无封面、按书名生成（可调背景色/文字色）、上传图片。生成的封面是 600×800 JPEG。

### 编辑原文

点「编辑原文」进入逐章编辑：点左侧章节载入该章，改完切换章节自动保存，`Ctrl+S` 手动保存，`Esc` 退出。

- 写回时只替换该章区间并平移后续章节的偏移量，不会触发全量重新分章，手工改过的章节名和层级都保留
- 「还原本章」退回该章**导入时的原文**
- 顶部「下载 TXT」按钮在原文有改动后才可点，导出保留原文件的换行风格（CRLF / LF）

### 生成

输出 `书名_作者.epub`，可在「书籍信息」页关掉作者只留书名。EPUB 3 规范，同时输出 NCX 以兼容老阅读器。

## 性能

用 766 万字 / 23.6 万行 / 1076 章的网文实测：

| 环节 | 耗时 |
|---|---|
| UTF-8 解码 | 187 ms |
| 正则分章 | 39 ms |
| 切章 + 生成 1076 个 XHTML | 164 ms |
| deflate 压缩 + ZIP 打包 | 680 ms |
| **端到端** | **约 1.3 秒** |
| 内存峰值 | 176 MB |

拖动排序的开销（同样 766 万字）：

| 操作 | 耗时 |
|---|---|
| 重排全文 + 重算 1076 个偏移 | 9 ms |
| 一次完整拖动 | 17 ms |
| 拖动中滚动重绘 | 15.9 ms/帧 |

## 与原版 EasyPub 的差异

保留：章节正则识别、章节改名/删除/层级、版式控制、CSS 自定义、封面生成、EPUB 输出。

**移除**：

- MOBI / AZW3 / kindlegen 输出（依赖 2014 年的 32 位闭源 exe，且 Amazon 2022 年起只收 EPUB）
- `ereaders.xml` 的 `res://` 字体路径映射（为 Sony PRS-505 / Nook 那代设备准备）
- 内嵌字体子集化

**改进**：

- 修复原版把正文误判成章节的问题
- 层级判定改为结构化解析（`第X卷` 是一级、`第X章` 是二级），不再靠字符包含
- 章节列表虚拟滚动，1076 章只渲染约 25 个 DOM 节点
- 全文编辑器实测不可行（766 万字定位要 3.3 秒、单字符输入 183 ms），改为逐章加载

## 技术实现

没有框架、没有依赖、没有构建步骤，全部是原生 JS。

| 文件 | 职责 |
|---|---|
| `js/zip.js` | 手写 ZIP 写入器。deflate 走浏览器原生 `CompressionStream('deflate-raw')`，不支持时降级为 STORED |
| `js/text.js` | 编码识别（BOM → 严格 UTF-8 试解码 → 回退 GB18030）、章节解析、正文转 XHTML |
| `js/epub.js` | EPUB 3 组装：OPF / NAV / NCX / XHTML / CSS |
| `js/cover.js` | Canvas 生成书名单色封面 |
| `js/app.js` | 界面逻辑：虚拟列表、拖动排序、逐章编辑、预览 |

几个值得记录的坑：

- **`textarea.value` 会把 CRLF 规范化成 LF**。不统一换行的话，编辑往返会被误判为「用户改过」，进而静默改写正文、覆盖章节标题。导入时统一转 LF，导出时按原格式还原。
- **`word-wrap` 是 `overflow-wrap` 的别名**。写成 `overflow-wrap: anywhere; word-wrap: break-word;` 会覆盖掉强值，兜底声明必须放前面。
- **中文行尾标点会悬挂溢出**。`“……”？` 这类收尾不能被拆到下一行，Chrome 会让整行溢出 7px 撑出横向滚动条。给段落留 `padding-right: 0.5em` 才能根治。
- **虚拟列表不能用 HTML5 拖拽**。滚动时重建 DOM 会让拖拽源节点消失，浏览器直接取消拖动。改用自定义鼠标事件实现。
- **点击时不要重建 DOM**，否则双击的第一下就把元素换掉了，`dblclick` 永远不触发。

## 开发与测试

测试用 CDP 驱动真实浏览器跑完整流程，断言在页面内执行。

```bash
# 先准备一份大样本（任意 700 万字级 txt）
cp /path/to/your.txt test/sample.txt

# 起服务器
python -m http.server 8848

# 跑测试（各开一个无头 Chrome）
node test/verify.js     # 批量操作、自定义 CSS、文件名
node test/verify3.js    # 目录页、长串换行、编辑与偏移平移、TXT 导出
node test/verify4.js    # 还原本章
node test/verify5.js    # 换书后的编辑状态隔离
node test/verify6.js    # 章节改名、内容简介标题
node test/verify8.js    # 前置页章节、拖动排序、nav 结构
node test/bench-drag.js # 拖动性能基准
```

`test/bookB.txt` 是 21 章小样本，用于换书对比，已入库。

EPUB 结构校验（mimetype 位置、manifest/spine 一致性、XML 合法性）：

```bash
python test/validate.py test/out.epub
```
